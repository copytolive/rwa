# VectorForge Historical Simulation Lab

Public GitHub Pages URL:

`https://narzulalistiqlal.github.io/rwa/backtest/`

VectorForge is a public multi-asset historical market research and simulation lab. It does not require Visual Studio Code or a locally running server.

## Public instrument universe

The public catalog is stored in `data/assets.json`. It currently contains 33 large/commonly traded instruments, all standardized on Dukascopy historical bid/ask tick data:

- 7 FX majors: EURUSD, GBPUSD, USDJPY, USDCHF, AUDUSD, USDCAD, NZDUSD.
- Large FX crosses: EURGBP, EURJPY, EURCHF, EURAUD, EURCAD, EURNZD, GBPJPY, GBPCHF, GBPAUD, GBPCAD, GBPNZD, AUDJPY, AUDCAD, AUDCHF, AUDNZD, CADJPY, CADCHF, CHFJPY, NZDJPY, NZDCAD, NZDCHF, USDCNH.
- Metals: XAUUSD, XAGUSD.
- Crypto quoted in USD: BTCUSD, ETHUSD.

`data/asset_status.json` is generated by GitHub Actions and records source-verification status, sample count, sample SHA-256 and verification timestamps. `data/validate_assets.cjs` retries multiple historical windows to avoid treating a temporary empty/failed request as permanent source failure.

Raw Dukascopy archives are deliberately not committed to this repository. Full-tick history across dozens of instruments can reach very large storage sizes. VectorForge instead keeps the catalog, provider metadata, hashes, requests and results public while fetching raw historical ticks from Dukascopy on demand.

## Interactive browser engine

The page currently supports:

- Legacy public EURUSD 1-second stream from 2009-05 through 2018-07.
- 111 indexed monthly EURUSD source files.
- Local custom TXT / CSV / TSV upload without uploading the source file to the repository.
- Price/SMA, SMA cross, EMA cross, RSI mean reversion and Donchian breakout models.
- Long + short, long only and short only.
- Stop distance, target ratio, spread, slippage and round-trip cost.
- Net R, positive-outcome rate, profit/gain-loss ratio, drawdown, expectancy, frequency, losing streak, long/short counts, signal count and sample count.
- SHA-256 browser-run fingerprint and JSON result export.

## Full-tick multi-asset execution

`backtest/chat/` is the GitHub execution plane for full-tick multi-asset research.

Flow:

1. A structured request is saved under `chat/requests/`.
2. `.github/workflows/vectorforge-chat.yml` starts automatically.
3. GitHub Actions downloads the requested Dukascopy bid/ask ticks.
4. `chat/run_chat_job.py` runs the historical simulation.
5. A public result is written to `chat/results/<request_id>.json`.
6. The result includes dataset SHA-256, evaluation ID, configuration and metrics.

This makes chat a control interface: a user can specify asset, dates, model, parameters and execution assumptions in chat while GitHub performs the historical compute and stores the auditable output.

## Verified GitHub batch factory

`.github/workflows/vectorforge-batch.yml` runs `factory/run_batch.py` on GitHub-hosted compute. The baseline campaign evaluates SMA periods 50 through 1500 in steps of 25 against verified EURUSD source months.

Each evaluation receives a deterministic ID based on:

`SHA256(dataset hash + month + model + parameters + engine version)`

Persistent outputs include:

- `results/latest_batch.json`
- `results/evaluation_ids.json`
- `results/batches.json`
- `results/shards.json`
- `results/campaign.json`

Duplicate evaluation IDs do not increase the verified count. Merkle shards allow the audit ledger to scale without storing one trillion individual hashes directly in Git.

## Automatic source and asset verification

- `vectorforge-batch.yml`: resumable EURUSD research campaign.
- `vectorforge-assets.yml`: verifies the public 33-instrument universe against real historical source samples.
- `vectorforge-chat.yml`: processes structured multi-asset historical backtest requests.
- `pages.yml`: validates the public site, JavaScript and audit ledgers before GitHub Pages deployment.

## One-trillion verification contract

The frozen scaling rules live in:

- `factory/scale_contract.json`
- `factory/TRILLION_SCALE.md`

`target_evaluations = 1,000,000,000,000` is a research objective, not a completed-count claim. A genuine trillion-evaluation campaign requires distributed/self-hosted compute workers while retaining the same dataset hashes, engine versions, evaluation rules and Merkle verification scheme.

VectorForge is historical research/simulation software only. It does not place broker or exchange orders.
