# VectorForge Historical Simulation Lab

Public GitHub Pages URL:

`https://narzulalistiqlal.github.io/rwa/backtest/`

VectorForge is a public multi-asset historical market research and simulation lab. It does not require Visual Studio Code or a locally running server.

## Public instrument universe

The production catalog is stored in `data/assets.json`. It currently contains 31 large/commonly traded instruments, all standardized on Dukascopy historical bid/ask tick data and retained only after automated source verification:

- 7 FX majors: EURUSD, GBPUSD, USDJPY, USDCHF, AUDUSD, USDCAD, NZDUSD.
- Large FX crosses: EURGBP, EURJPY, EURCHF, EURAUD, EURCAD, EURNZD, GBPJPY, GBPCHF, GBPAUD, GBPCAD, GBPNZD, AUDJPY, AUDCAD, AUDCHF, AUDNZD, CADJPY, CADCHF, CHFJPY, NZDCAD, NZDCHF.
- Metals: XAUUSD, XAGUSD.
- Crypto quoted in USD: BTCUSD, ETHUSD.

`data/asset_status.json` is generated by GitHub Actions and records source-verification status, sample count, sample SHA-256 and verification timestamps. The production universe is currently 31/31 source-verified.

Raw Dukascopy archives are deliberately not committed to this repository. Full-tick history across dozens of instruments can reach very large storage sizes. VectorForge instead keeps the catalog, provider metadata, hashes, requests and results public while fetching raw historical ticks from Dukascopy on demand.

## Interactive browser engine

The page supports the legacy public EURUSD 1-second stream from 2009-05 through 2018-07, local custom TXT/CSV/TSV uploads, Price/SMA, SMA cross, EMA cross, RSI mean-reversion and Donchian models, long/short filters, stop/target/spread/slippage/cost assumptions, detailed R metrics, SHA-256 browser fingerprints and JSON export.

## Full-tick multi-asset execution

`backtest/chat/` is the GitHub execution plane for full-tick multi-asset research.

Flow:

1. A structured request specifies instrument, dates, model and execution assumptions.
2. GitHub Actions downloads the required Dukascopy bid/ask ticks.
3. `chat/run_chat_job.py` performs the historical simulation.
4. The result is stored publicly under `chat/results/<request_id>.json`.
5. Every successful result includes a dataset SHA-256 and deterministic evaluation ID.

This makes chat a control interface: an owner can simply request a backtest in ChatGPT and the GitHub pipeline performs the historical compute and stores the auditable output.

## Public request mode

The GitHub Pages site also contains a public request builder. It opens a pre-filled GitHub issue. `.github/workflows/vectorforge-public-request.yml` validates that issue, fetches Dukascopy ticks, runs the backtest, commits the request/result, and posts the public result link back to the issue.

Public requests are capped at 7 calendar days per job to protect shared GitHub Actions compute. Longer owner/research jobs can use the chat-controlled request path.

## Verified GitHub batch factory

`.github/workflows/vectorforge-batch.yml` runs the resumable baseline research campaign. Evaluation IDs are deterministic:

`SHA256(dataset hash + month + model + parameters + engine version)`

Persistent outputs include `results/latest_batch.json`, `results/evaluation_ids.json`, `results/batches.json`, `results/shards.json`, and `results/campaign.json`. Duplicate evaluation IDs do not increase the verified count. Merkle shards allow the audit ledger to scale without storing one trillion individual hashes directly in Git.

## Automation and QA

- `vectorforge-assets.yml`: verifies the public Dukascopy instrument universe.
- `vectorforge-chat.yml`: processes structured owner/chat multi-asset requests.
- `vectorforge-public-request.yml`: processes capped public GitHub issue requests.
- `vectorforge-batch.yml`: resumable research campaign.
- `pages.yml`: validates site files, JavaScript/Python syntax, catalogs and audit ledgers before deployment.

## One-trillion verification contract

The frozen scaling rules live in `factory/scale_contract.json` and `factory/TRILLION_SCALE.md`.

`target_evaluations = 1,000,000,000,000` is a research objective, not a completed-count claim. A genuine trillion-evaluation campaign requires distributed/self-hosted compute workers while retaining the same dataset hashes, engine versions, evaluation rules and Merkle verification scheme.

VectorForge is historical research/simulation software only. It does not place broker or exchange orders.
