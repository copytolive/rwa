RENKO V11 — TradingView rule parity, wick formation & projection rules
ATR

ATR is calculated from the regular source chart with Wilder/RMA smoothing. The latest ATR snapshot becomes one chart-wide brick size for the rebuild. Default length: 14.

Traditional

A fixed absolute box size. Same-direction continuation needs one box. Direction reversal needs two boxes.

Percentage (LTP)

The selected percentage is applied to the latest completed source close, rounded to the Binance minimum tick size, then applied consistently to all displayed bricks. Default: 1%.

Source: Close

Historical brick formation uses the close of each selected source interval. Wicks represent the most extreme source closes accumulated before the next brick locks.

Source: OHLC

Historical formation uses each source bar's O/H/L/C range. Live projection uses actual incoming trades, so current-interval movement is not approximated.

Wicks

Only low wicks appear on up bricks; only high wicks appear on down bricks. The wick carries discarded opposite movement since the previous locked brick instead of copying every source candle's full high/low onto every Renko brick.

Projection bricks

Incoming live prices build translucent projection bricks. One or more full projections plus a partial projection can appear. They can recalculate and disappear. Only after the selected source interval closes does rebuilt history become locked.

Price integrity

Renko open/close levels are synthetic. The blue REAL line and hard-stop check use the live Binance market price; synthetic brick prices are not treated as guaranteed fills.

Parity boundary

TradingView's proprietary historical intrabar ordering is not public. V11 reproduces the documented methods, thresholds, source behavior, wick directionality, tick-size rounding and projection/locking model. For OHLC bars whose High and Low were both crossed inside the same historical interval, exact proprietary ordering cannot be independently certified from OHLC data alone.
