RENKO V12 — tick formation, immediate close & wick rules
Tick formation

There is no 1m/3m/5m chart interval. Every incoming Binance trade is processed immediately against the current Renko thresholds.

Immediate multi-brick close

If one real trade jumps across five box thresholds, five bricks are confirmed in that same processing event. Nothing waits for a candle close.

Traditional

A fixed absolute box size. Same-direction continuation needs one box. Direction reversal needs two boxes.

Percentage (LTP)

The percentage is applied to the symbol-load last traded price snapshot, rounded to Binance minimum tick size. Formation after sizing remains tick-by-tick.

ATR

ATR is used only to assign the box size. Because ATR mathematically requires bars, V12 calibrates it from recent completed 1-minute bars internally. That hidden calibration never delays brick confirmation: trades still lock bricks immediately.

Wicks

Wicks use actual trade extremes accumulated before the next brick forms. Up bricks can carry the discarded low excursion; down bricks can carry the discarded high excursion.

History

Recent history is reconstructed from Binance public aggregate trades, then live operation uses individual @trade events. Older trades load when you pan left.

Execution

Renko levels are synthetic thresholds. The blue REAL line and hard-stop check use the actual current Binance market price.

Important difference from TradingView interval-lock Renko

V12 intentionally follows the requested tick-native behavior. It does not wait for TradingView-style source-interval confirmation. This removes the exact problem where price already crosses several boxes but bricks remain unconfirmed until a 1-minute candle closes.
